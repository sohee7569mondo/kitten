### 결론: 저장 실패가 아니라 "저장은 됐는데 화면에 안 그려지는" 문제

가장 유력한 연쇄 원인은 이렇습니다.

1. 코드가 **클래식 블록**으로 들어감
2. → 워드프레스가 `wpautop`으로 `<p>`·`<br>`을 자동 삽입해 `<style>`/`<script>`를 훼손
3. → `<script>`가 깨져서 **여섯 개의 문 카드 6장이 아예 안 그려짐** (원래 코드는 카드를 JS로 생성)
4. → 동시에 `.reveal{opacity:0}` 상태로 굳어 **무료운세·철학·CTA 섹션이 전부 투명**해짐
5. → 결과적으로 히어로 말고는 거의 빈 화면 = "달라진 게 없다"

### 캐시인지 아닌지 30초 만에 가르는 법

WordPress.com은 **로그인한 관리자에게는 캐시를 우회**해서 항상 최신을 보여줍니다.

- 사장님이 **로그인 상태에서 안 바뀜** → 캐시 문제가 **아님**. 진짜 렌더링 문제 (위 1~5번)
- **시크릿 모드(로그아웃)에서만 옛날 것** → 캐시 문제. 아래 캐시 비우기로 해결

## 3. v5 대비 바뀐 점

**깨짐 방지 (이번 문제의 실질적 해결)**
- `<!-- wp:html -->`로 감싸 Custom HTML 블록으로 삽입 → `wpautop` 훼손 차단
- 여섯 개의 문 카드 6장을 **JS 생성 → 정적 HTML**로 변경. JS가 죽어도 카드가 남습니다
- `.reveal` 기본값을 **보임**으로 뒤집음. JS가 붙었을 때만 숨겼다가 등장시킵니다 → 빈 화면 원천 차단
- IntersectionObserver 미지원/실패 대비 폴백 + 3초 안전장치 추가
- 게이트 애니메이션을 `backwards`로 변경 → 애니메이션이 안 돌아도 히어로가 안 사라짐
- 하단 `BUILD v6` 버전 도장 추가

**워드프레스 충돌 제거**
- 모든 CSS를 `#stellar-home` 안으로 스코프. 전역 `*{margin:0}`과 `section{padding:120px}`이 테마·관리자바를 건드리던 문제 제거
- 테마 폭 제한 탈출을 `margin-left:calc(50% - 50vw)`로 처리 (가로 스크롤 안 생김 — 데스크톱/모바일 둘 다 검증)
- 로그인 시 관리자바 32px만큼 상단 메뉴 자동 하강
- `.stars` 배경을 `z-index:-1` → `0`으로. 스태킹 컨텍스트에 갇혀 사라지던 위험 제거

**용량·속도**
- base64 인라인 **1.98MB → 32KB** (이미지는 미디어 라이브러리 + WebP, 총 832KB, lazy-load)
- 모든 `<img>`에 `width`/`height` 지정 → 레이아웃 밀림(CLS) 제거
- 히어로 이미지 `fetchpriority="high"`

**내용**
- 무료 운세 4칸 → **6칸**. 링크 없이 떠 있던 `이번주 띠별운세`·`이번주 사주 총평` 연결
- 모든 링크를 실제 주소로 교체 (`saju.html` → `/saju/` 등)
- 여섯 개의 문은 판매 페이지가 아직 없어 **"준비중" 뱃지 + 링크 없음** 상태
  (페이지 생기면 카드의 `<div class="door-card">` → `<a class="door-card" href="/주소/">`, 닫는 `</div>` → `</a>`)
- 스타운세 배너는 `/stars/`를 가리킵니다 — **이 페이지는 아직 없습니다.** 만들거나 배너 `<section>`을 지우세요

**한글 조판**
- `word-break:keep-all` 적용. "기다/립니다"처럼 단어 중간에서 끊기던 문제 해결
- 히어로 제목 3줄 → 2줄, 모바일 섹션 여백 축소
