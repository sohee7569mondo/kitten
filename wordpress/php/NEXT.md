### 이 과정에서 알게 된 것 두 가지

**REST 는 nonce 없이는 로그인을 안 잡습니다.** 브라우저에서
`/wp-json/stella/v1/me` 를 그냥 부르면 로그인 상태여도 `member:false` 가
옵니다. 그래서 `wp_head` 에 `window.STELLA_NONCE` 를 심는 스니펫
(「스텔라 로그인 열쇠」)을 만들고, 부를 때 `X-WP-Nonce` 를 같이 보냅니다.
서버 안에서 확인할 때는 `rest_do_request()` 를 쓰면 nonce 가 필요 없습니다
— 이게 `?stella_me=1` 점검판이 하는 방식입니다.

**⚠ 스니펫 416 「Snippet login nonce」의 원본이 사라졌습니다.** 진단 코드를
「718 을 열어 전부 지우고」로 여러 번 반복해 드리다가 사용자가 416 을 열어
덮어썼습니다. 사본이 없습니다. 이름으로 미루어 위의 nonce 일을 하던 것으로
보이고, 그 기능은 「스텔라 로그인 열쇠」로 대신 만들었습니다.
**앞으로 진단 코드는 매번 새 스니펫으로 만들고, 기존 스니펫을 덮어쓰라고

### 나이 기준을 어떻게 정했나 (중요 — 근거가 남아 있어야 합니다)

처음에 손님 본인의 대운으로 잘랐습니다 (초년 = 첫 두 판, 중년 = 3~6번째 판,
말년 = 7번째 판부터). 그러면 말년이 만 예순 언저리에 시작해서, 사이트
주인이 든 「연금 받을 때가 말년」이라는 감과도 맞았습니다.

그런데 다른 사이트들이 쓰는 숫자를 확인해보니 훨씬 이릅니다. 가장 널리
쓰이는 근묘화실 틀은 년주 0~15세, 월주 15~30세, 일주 30~45세, 시주 45세~
입니다. 「말년 45세부터」가 여러 출처에서 가장 반복적으로 나오는 숫자예요.

사이트 주인의 결정 — **「그냥 사주에서 다른 사이트들이 많이 하는 나이로
자르자, 우리만 튀어나오지 않게」**, 그리고 「대세에 따르자」.

그래서 최종 기준은 이것입니다. 네 문이 모두 같은 기준을 씁니다.

    초년 = 만 0 ~ 29세   (년주 + 월주)
    중년 = 만 30 ~ 44세  (일주)
    말년 = 만 45세 이후  (시주)

말년이 마흔다섯에 시작하는 것이 손님에게 이르게 느껴질 수 있어서, 글에서
「말년은 늙는 시기가 아니라 앞에서 쌓은 것으로 사는 시기」라고 분명히
짚어둡니다. 이 문장을 지우지 마세요. 환불 이야기가 나올 자리입니다.

**달라야 하는 것** — 그 결과를 풀어주는 모든 문장. 조언, 예시, 「한마디로」,

### 크게 헤맨 두 가지 — 다시 밟지 말 것

**1. parse_query 에 손대면 페이지가 통째로 가려진다**

옛 `?s=` 링크를 살리려고 이렇게 썼다가 유앤미 화면이 며칠 안 떴다.

```php
if ( ! isset( $q->query_vars['s'] ) ) { return; }   // 늘 참이다!
unset( $q->query_vars['s'] );
$q->is_404 = false;
```

워드프레스는 `fill_query_vars()` 로 `s` 를 **언제나 빈 값으로 채워 둔다**.
그래서 「s 가 있을 때만」이라는 가정이 틀렸고, 유앤미를 열 때마다 쿼리를
건드려 페이지를 못 찾게 만들었다. **워드프레스의 페이지 찾기(parse_query·
pre_get_posts)에는 손대지 않는다.** 주소를 바꿔야 하면 init 에서
REQUEST_URI 만 고쳐 놓고 비켜선다(⑧번이 그 방식).

**2. 이 사이트는 물음표 뒤가 안 닿을 때가 있다**

`?stella_um2=1` `?um_font=1` 같은 진단이 통째로 홈으로 갔다. 같은
스니펫인데 `/um-card/...` 는 되고 `?um_card=1&...` 는 안 됐다.
카카오 디버거도 물음표 붙은 주소를 Invalid URL 로 물리쳤다.

→ **손님이 쓰는 주소와 서버가 부르는 주소는 모두 경로식으로 짠다.**
   진단도 경로식으로 만들어야 열린다.
