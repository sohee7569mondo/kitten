# 확인 도구 셋

패치를 만들기 전에 **사이트의 실제 상태**를 되살리고, 만든 뒤에 **책이
제대로 그려지는지** 확인합니다. 2026-09-07 에 byline 패치가 안 걸린
일이 있어서 만들었습니다 — 저장소 사본(`pages/reading-book.html`)에는
사이트에 이미 들어간 패치가 빠져 있어서, 그 위에서 잡은 자리가
사이트에서는 0군데로 나왔습니다.

## 1. recon.py — 사이트 상태 되살리기

`pages/reading-book.html` 에 `php/` 의 적용된 패치를 차례로 먹입니다.
결과는 `live_recon.html`. **새 패치는 반드시 이 파일 위에서 잡습니다.**

    python3 recon.py

`ORDER` 목록에 적용 순서대로 패치 이름을 적어둡니다. 이미 들어간
자리는 0군데로 나오는데, 그건 건너뜁니다(사본이 중간 상태일 수 있음).

## 2. render.js — 책 그려보기

페이지에서 `<script>` 31개를 뽑아 `vm` 안에서 차례로 돌리고,
`bkBook` 의 innerHTML 을 꺼냅니다.

    node render.js <blocks디렉터리> <견본이름>

견본 이름은 `door-love` `door-love-2` `door-career` … 열둘.

**주의 — 이 틀로 확인이 안 되는 것**

* 브라우저에서 화면을 고쳐 끼우는 후처리 (예: SUM-3 「정리하면」).
  가짜 DOM 이라 `getElementsByTagName` 이 빈 배열을 돌려주고 물러납니다.
  이런 자리는 넣고 나서 사이트에서 눈으로 봐야 합니다.
* 그림, 글꼴, 스크롤 길이, 폰에서의 줄바꿈.

## 3. chain.py — 넣는 순서대로 이어 먹이기

여러 패치를 손님이 넣을 순서 그대로 이어서 먹여, **각 자리가 제 차례에
한 군데씩** 걸리는지 봅니다. 앞 패치가 뒤 패치의 자리를 건드리면 여기서
잡힙니다.

    python3 chain.py

## 늘 하는 순서

1. `recon.py` 로 사이트 상태를 되살린다
2. 그 위에서 자리(정규식)를 잡는다 — 한 군데씩인지 센다
3. `php -l` (앞에 `<?php` 붙여서)
4. PHP 로 실제 `preg_replace` 를 돌려본다
5. `<script>` 31개를 뽑아 `node --check`
6. `render.js` 로 견본 열두 권을 그려 오류 0 인지 본다
7. 여러 패치면 `chain.py`

## 넘어가면 안 되는 것

* **`<script>` 안에 `&&` 나 홑 `&` 를 넣지 않습니다.** `||` 는 됩니다.
* 페이지 내용을 `wp_update_post` 로 저장하면 워드프레스가 `<script>` 를
  지웁니다. 반드시 `$wpdb->update()` 로 씁니다.
* WPCode 스니펫 위치는 **「어디서나 실행 / Run Everywhere」**.
  기본값인 「사이트 전체 헤더」로 두면 진단 주소가 홈으로 넘어갑니다.
* 한글은 손으로 `\uXXXX` 로 바꾸지 않습니다. 따옴표 친 heredoc 으로
  파일에 쓰고 그 파일을 읽습니다.
