### 다시 이러지 않으려면

**설정을 훑어 찍는 도구를 만들 때는 가릴 이름부터 먼저 정합니다.**
`patch160_money` 는 이제 이렇게 합니다 —

    이름에 SECRET · KEY · TOKEN · PASS · PW · REST · CHANNEL · STORE · HOOK
    이 들어가면 앞 네 글자만 남기고 ● 로 가립니다.
    다만 숫자 · 참거짓 · 열두 자보다 짧은 글자는 가리지 않습니다
    (STELLA_PW_MIN 이 8 인데 「8●●●●●●●● (1자)」로 나와 헷갈렸습니다).

**앞 네 글자는 일부러 남깁니다.** 그것만으로는 열쇠를 알아낼 수 없고,
새 열쇠가 실제로 들어갔는지 대보기에는 충분합니다. 실제로 이 네 글자로
「재발급은 했는데 사이트에는 아직 옛 열쇠」인 것을 잡았습니다.

## ② 열쇠가 어디 적혀 있나 — patch160_wherekey

    ?stella_wherekey=1   (관리자만)

wp-config.php 와 WPCode 스니펫 전부를 훑어 `define` 을 찾습니다.

**글자로 'define' 을 찾으면 안 됩니다.** 처음에 그렇게 만들었다가

    if ( defined( 'STELLA_PORTONE_SECRET' ) ) {     ← 읽기만 하는 곳
    define('STELLA_PORTONE_SECRET', '...');          ← 설명(주석) 안의 본보기
    define( 'STELLA_UM_KAKAO_REST', '' );            ← 비워둔 대비값

셋을 다 「여기 고치세요」로 잘못 짚었습니다. 소희 님이 세 번 헛걸음하셨습니다.

**고침 — `token_get_all()` 로 PHP 자신에게 물어봅니다.**

    · 주석 안의 define 은 T_COMMENT 한 덩어리라 아예 안 잡힙니다
    · defined 는 T_STRING 값이 'defined' 라 저절로 걸러집니다
    · 값은 T_CONSTANT_ENCAPSED_STRING 토큰이라 정규식으로 자를 일이 없습니다
    · 값이 빈 문자열이면 「비워둔 대비값 · 고칠 자리가 아닙니다」

☞ **코드에서 무엇을 찾을 때는 글자가 아니라 토큰으로 찾습니다.**
